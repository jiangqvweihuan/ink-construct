# 局域网联机设计说明（主机权威 + 客户端镜像）

> 目标：同一局域网内自动发现与配对，双人同房间协作，主机权威模拟，客户端发送输入并镜像渲染。
> 约束：不改变单机/无尽模式的战斗逻辑与数值；所有新增分支仅在联机模式下开启。

## 1. 角色分工

| 角色 | 职责 |
|---|---|
| 主机（Host） | 跑完整战斗：P1（本机输入）+ P2（远端输入）；敌人/Boss/波次/结算全部由主机推进；按 20Hz 下发快照 |
| 客户端（Client） | 不跑 AI 与敌人逻辑：本地玩家与敌人均为“受控镜像”，只根据快照设置位置/血量/状态/动画；按 30Hz 上送输入 |

主机玩家 id 恒为 1；客户端由 ENet 分配（≥2）。对局最多 2 人（1 主机 + 1 客户端）。

## 2. 端口与自动发现

| 项 | 值 |
|---|---|
| 游戏传输 | ENet/UDP，端口 `42420` |
| 发现信标端口（主机监听） | UDP `42420` |
| 发现扫描端口（客户端监听） | UDP `42421` |
| 信标频率 | 1.0s |
| 房间过期 | 3.5s 未收到信标即从列表移除 |

发现流程：

1. 主机绑定 `42420` 监听探测包，并向 `255.255.255.255:42421` 广播信标（JSON）。
2. 客户端绑定 `42421` 接收信标，同时每 1s 向 `255.255.255.255:42420` 与 `127.0.0.1:42420` 发探测包，主机单播回复。
3. 客户端解析 `app`/`version` 匹配的房间，按 `host_ip` + `port` 加入。
4. 广播被系统拦截时，客户端仍可用大厅中的“手动输入 IP”加入（兜底）。

## 3. 传输协议

ENet 通道划分（`rpc_config` 指定）：

| 通道 | 用途 | 模式 |
|---|---|---|
| 0 | 控制/大厅/事件（加入、就绪、开局、房间切换、会话结束、重连） | RELIABLE |
| 1 | 输入帧 | UNRELIABLE_ORDERED |
| 2 | 世界快照 | UNRELIABLE_ORDERED |

消息封包（输入/快照，便于单测与坏包丢弃）：

```
[magic u8=0x49][type u8][ver u8=1][seq u32][len u16][payload...][crc32 u32]
```

- 校验失败/版本不符/长度不符 → 丢弃并计数，不抛错。
- 快照与输入带序号；客户端丢弃旧快照，主机丢弃重复/过期输入。
- 丢失由 ENet 与“下一帧全量快照”天然自愈，无需逐条确认重传。

## 4. 会话状态机

```
IDLE -> HOSTING / JOINING -> LOBBY -> PLAYING -> (SETTLED) -> LOBBY / IDLE
                     ^          |
                     +-- 重连 --+
```

- `LOBBY`：成员列表、就绪状态、房主开始对局。
- `PLAYING`：房间内同步；主机推进房间与结算。
- 结束：主机 `session_end`，双方回大厅/模式选择。

## 5. 输入同步（客户端 -> 主机）

输入帧：

```json
{"seq": 12, "axis": -1, "held": ["jump", "attack"], "just": ["dash"]}
```

- 客户端按 30Hz 采样 P2 键位（方向键 + 小键盘），`just` 为本间隔内的按下沿。
- 主机把输入写进 `LanNet` 的远端输入缓冲；P2 的 `player.gd` 在“主机 + 槽位 1”时改读该缓冲：
  - `_pressed` → `remote_held`
  - `_just` → `take_remote_just`（读取即消费）
  - `_move_axis` → `remote_axis`
- 主机每帧末不支持“积压帧回放”，输入直接作用于当前物理帧（局域网 RTT 低，足够）。

## 6. 世界快照（主机 -> 客户端，20Hz）

```json
{
  "seq": 88,
  "ps": [[slot, x, y, hp, max_hp, state, facing, anim, loop, skull_id, dead], ...],
  "es": [[net_id, scene, type_id, x, y, hp, max_hp, state, facing, anim, loop], ...],
  "run": {"mode": "adventure", "difficulty": 1, "room": 0, "depth": 1,
          "boss": "c001", "phase": 0, "upgrades": {}, "blessing": "hp",
          "cleared": false}
}
```

客户端处理：

- 玩家：按 `slot` 找到本地镜像，插值位置，写入血量/状态/朝向，动画变化时调用 `_play(anim, loop)`。
- 敌人：按 `net_id` 建/删镜像节点（`load(scene)` + `net_puppet = true`）；快照里缺失且超过 0.3s 的镜像移除。
- `run`：覆盖本地 `Run` 的展示字段，保证 HUD/房间名与主机一致。

## 7. 断线重连与异常

| 场景 | 处理 |
|---|---|
| 客户端意外断线 | 自动重试加入（携带 `resume_token`），间隔 1s，最多 5 次；期间 UI 显示重连进度 |
| 主机保留席位 | 断线后保留 30s；重连成功恢复原槽位并下发当前快照 |
| 客户端心跳 | 2s 一次 `ping`，6s 无 `pong` 视为链路异常并触发重连 |
| 主机判定离线 | 5s 无输入标记“不稳定”，15s 无输入移除成员（对局继续，P2 站立） |
| 坏包/版本不符 | 丢弃并计数，连续异常超过阈值提示 |
| 房间满员 | 加入被拒，原因回传 UI |
| 端口占用 | 创建房间失败并提示（发现层降级为手动 IP） |

## 8. 代码结构

| 文件 | 职责 |
|---|---|
| `scripts/net/net_config.gd` | 端口、版本、协议常量、动作表 |
| `scripts/net/net_protocol.gd` | 封包/解包/CRC/输入与快照校验 |
| `scripts/net/lan_discovery.gd` | UDP 广播信标、扫描、房间列表 |
| `scripts/net/lan_net.gd` | 自动加载：主机/加入、会话、RPC、远端输入、重连 |
| `scripts/net/net_sync.gd` | 房间内快照生产/消费、镜像管理、房间推进 |
| `scripts/ui/lan_panel.gd` | 局域网大厅（创建/扫描/加入/成员/开始） |
| `scripts/ui/mode_select.gd` | 局域网入口改为打开大厅 |
| `scripts/world/room_01.gd` | 主机双人 / 客户端镜像两种构建路径 |
| `scripts/player/player.gd` | `net_puppet` 受控分支 + 远端输入读取 |
| `scripts/enemies/c016.gd` 及各 Boss | `net_puppet` 早退，快照驱动 |
| `scripts/systems/run_state.gd` | `net_role` / `net_slot` 标记 |

## 9. 单机不受影响的保证

- 所有新增分支以 `Run.net_role != ""` 或 `net_puppet == true` 为前提；单机时路径与数值完全不变。
- 敌人/Boss 只在 `net_puppet` 为真时跳过 AI；默认值 false。
- 设置、改键、触屏方案、存档结构不改。

## 10. 测试方案

| 层级 | 内容 |
|---|---|
| 单元测试 | 封包往返、CRC 坏包丢弃、序号过期丢弃、输入/快照字段校验、房间信标解析 |
| 集成测试（双进程） | 本机 `--headless` 起主机与客户端：自动发现 → 加入 → 就绪 → 开局 → 输入同步 → 快照同步 → 客户端主动断开 → 自动重连恢复 → 正常离开 |
| 场景冒烟 | 单人流程不受影响；联机房间主机/客户端各构建一次无脚本错误 |

## 11. 已知限制

- 客户端为纯镜像，不含本地预测；LAN 下延迟约 1 个快照周期（50ms）。
- 客户端不显示伤害数字与部分打击特效（表现层差异），血量与动作同步。
- 仅支持 2 人；跨网段/公网需要端口映射，不在本次范围。
