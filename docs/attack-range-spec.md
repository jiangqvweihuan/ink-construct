## 一、判定模型（先说清"打到哪里算打到"）

| 项目 | 规则 |
|---|---|
| 判定原点 | 角色节点原点（脚底中心），水平距离 `dx = 目标中心.x - 自身原点.x` |
| 水平判定 | `|dx| <= range`（`range` 的世界像素 = 骨架伸展像素 × 该形态 `scale`） |
| 垂直判定 | 玩家普攻固定 `dy <= 70`；玩家技能用 `height`；敌人用 `hit_height` |
| 朝向判定 | `in_front = (dx == 0) or (sign(dx) == facing)`，即只打正前方 |
| `both` 例外 | 回身横扫 / 武器越过原点甩到身后的招式，配置 `both: true` 后前后两侧都判 |
| 判定时刻 | 出了起手后第 `hit_at` 秒结算，单位=动画秒；等于武器/身体伸到最远端的时刻 |
| 提前量 | **已删除** 旧的统一提前 10%（`hit_at * 0.9`），它是"动画还没打到就掉血"的系统性根源 |
| 收招 | 锁定时长取动画真实时长（Boss/小怪由骨架查表，玩家技能 `_skill_durations` 运行时缓存） |

判定代码位置：[player.gd](file:///e:/GodotProjects/ink-construct/scripts/player/player.gd)（`_deal_hit` / `_deal_skill_hit`）、[c016.gd](file:///e:/GodotProjects/ink-construct/scripts/enemies/c016.gd)（`_attack_tick` / `_deal_hit`）、[boss.gd](file:///e:/GodotProjects/ink-construct/scripts/enemies/boss.gd)（冲锋判定）。

## 六、数据来源与复测流程

1. 运行 `scenes/tests/range_probe.tscn`，洋红背景、`PROBE_SCALE = 0.35`、`ORIGIN = (640, 660)`、60Hz 采样，逐帧记录剪影左右最远像素，写入 `tests/out/reach.json`，格式 `[t, 左侧伸展, 右侧伸展]`（单位=scale 1 骨架像素）。
2. 取攻击动画中伸展的**局部峰值时刻**作为 `hit_at`；取峰值所在一侧的伸展量作为 `range` 的骨架像素基数。
3. `range = 骨架像素 × 该形态 scale`；若峰值落在原点左侧而美术朝右，则该招标记 `both`。
4. 修改后跑回归：`boss_test`（`_debug` / `c009` / `c015a1` / `c001` 均跑到 `ALL DONE`：登场→两次变身→冲锋→斩杀→结算）、`player_test`、`room_test`。

### 判定与实测的对应关系

- 判定距离以**角色节点原点**为基准，剪影测量同样以原点为基准（root motion 造成的位移已包含在剪影里，两者自洽）。
- 剪影包含披风、背挂武器等非攻击部件，个别招式（c009 skill07/08）峰值被坐骑主体主导，只按实测微调 range，判定时刻保留原值。

## 七、已知局限 / 后续素材库阶段要复核的点

- c023（敌方游魂弓手）的三招时长未单独采样（表中以 `—` 标注），其范围来自探针实测骨架像素。
- c001 skill03 的剪影峰值在动画第 0 帧（车体本身最宽），命中取挥击中段 1.0s，属于"按动画节奏取中段"的折中。
- 玩家普攻垂直容差固定 70px：若后续加入浮空/高低差敌人，需要在 `_deal_hit` 里改成按招式配置。
