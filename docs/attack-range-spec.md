# 攻击模式与判定范围标定表

> 本文档汇总当前项目里 **5 个玩家形态 / 7 种小怪与精英 / 5 个 Boss（+1 个测试占位）** 的全部攻击招式、判定时刻、判定范围与 AI 起手参数。
> 所有 `hit_at` 与 `range` 都来自 `scenes/tests/range_probe.tscn` 的逐帧剪影采样（`tests/out/reach.json`）与 Spine 冻结帧视觉复核，不是手填估值，也不能只取最远峰值。

## 一、判定模型（先说清"打到哪里算打到"）

| 项目 | 规则 |
|---|---|
| 判定原点 | 角色节点原点（脚底中心），水平距离 `dx = 目标中心.x - 自身原点.x` |
| 水平判定 | `|dx| <= range`（`range` 的世界像素 = 骨架伸展像素 × 该形态 `scale`） |
| 垂直判定 | 玩家普攻固定 `dy <= 70`；玩家技能用 `height`；敌人用 `hit_height` |
| 朝向判定 | `in_front = (dx == 0) or (sign(dx) == facing)`，即只打正前方 |
| `both` 例外 | 回身横扫 / 武器越过原点甩到身后的招式，配置 `both: true` 后前后两侧都判 |
| 判定时刻 | 出了起手后第 `hit_at` 秒结算，单位=动画秒；取武器/身体实际进入有效攻击位置的画面，最远伸展峰值只作候选，必须逐帧复核 |
| 提前量 | **已删除** 旧的统一提前 10%（`hit_at * 0.9`），它是"动画还没打到就掉血"的系统性根源 |
| 收招 | 锁定时长取动画真实时长（Boss/小怪由骨架查表，玩家技能 `_skill_durations` 运行时缓存） |

判定代码位置：[player.gd](file:///e:/GodotProjects/ink-construct/scripts/player/player.gd)（`_deal_hit` / `_deal_skill_hit`）、[c016.gd](file:///e:/GodotProjects/ink-construct/scripts/enemies/c016.gd)（`_attack_tick` / `_deal_hit`）、[boss.gd](file:///e:/GodotProjects/ink-construct/scripts/enemies/boss.gd)（冲锋判定）。

## 三、小怪 / 精英（7 种）

### 3.0 敌人技能释放准则（长期有效）

后续优化普通怪与精英时，统一遵守以下规则；不能只缩短总冷却或把所有招式等权随机：

1. **普通攻击是默认出手**：近身且没有合规特殊招式时，必须使用招式 1 或继续贴近，普攻应占绝大多数出手。
2. **特殊招式必须有触发限制**：按招式定位明确距离窗口、追击 / 近身状态或其他条件；高伤、远程、位移招式不得进入近身等权随机池。
3. **特殊招式必须有独立冷却**：独立冷却从实际起手时开始计时，不能只依赖全局攻击间隔；升龙类高伤位移招式的独立冷却不得低于 10 秒。
4. **不合规就不释放**：特殊招式处于冷却或不在触发窗口时，回到合规普攻或继续贴近，禁止拿远距离招式违规兜底。
5. **数值集中配置**：权重、独立冷却、距离窗口与主动触发方式写入 `enemy_types.gd` 的 `attack_rules`，测试需覆盖冷却禁重入、到点可放、距离窗口和普攻占比。

刀客当前落地值：亡命三刀为默认普攻，近身随机权重 6；双镰权重 1、限 164px 内、独立冷却 6 秒；螺旋鞭只在 180～400px 主动触发、独立冷却 8 秒；升龙刀只在原追击瞬身窗口触发、独立冷却 12 秒。双镰可用时近身理论抽取比例为 6:1，其冷却期间全部回到亡命三刀。

蛮兵当前落地值：开天为默认普攻，近身随机权重 7；辟地权重 1、限 164px 内、独立冷却 9 秒；赶山三斧只在追击 120～260px 窗口主动触发、独立冷却 16 秒，不进入近身随机池。连段前半以 85px/s 推进，两劈各 1 伤，随后原地大劈 2 伤并静默力竭 3 秒；力竭属于同一招恢复段，不显示控制提示。被动「蛮力」让每段实伤附带 140px/s 水平的短击退初速，并提供全程霸体；普通控制、受击硬直与直接牵引无效，`ignore_armor` 控制与时停仍可穿透。

## 六、数据来源与复测流程

1. 运行 `scenes/tests/range_probe.tscn`，洋红背景、`PROBE_SCALE = 0.35`、`ORIGIN = (640, 660)`、60Hz 采样，逐帧记录剪影左右最远像素，写入 `tests/out/reach.json`，格式 `[t, 左侧伸展, 右侧伸展]`（单位=scale 1 骨架像素）。
2. 先用伸展的局部峰值筛选候选时刻，再用 Spine 冻结帧逐帧核对武器真正扫入有效攻击位置的画面，以该画面确定 `hit_at` 与同帧伸展量；不得把后段举斧、转身或收招的最远姿势误当命中帧。
3. `range = 命中帧骨架像素 × 该形态 scale`；若武器实际扫到原点左侧而美术朝右，则该招标记 `both`。
4. 修改后跑回归：`boss_test`（`_debug` / `c009` / `c015a1` / `c001` / `c008` / `c032` 均跑到 `ALL DONE`：登场→两次变身→冲锋→斩杀→结算）、`player_test`、`room_test`。

### 判定与实测的对应关系

- 判定距离以**角色节点原点**为基准，剪影测量同样以原点为基准（root motion 造成的位移已包含在剪影里，两者自洽）。
- 剪影包含披风、背挂武器等非攻击部件，个别招式（c009 skill07/08）峰值被坐骑主体主导，只按实测微调 range，判定时刻保留原值。
