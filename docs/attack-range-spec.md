## 一、判定模型（先说清"打到哪里算打到"）

| 项目 | 规则 |
|---|---|
| 判定原点 | 角色节点原点（脚底中心），水平距离 `dx = 目标中心.x - 自身原点.x` |
| 水平判定 | `|dx| <= range`（`range` 的世界像素 = 骨架伸展像素 × 该形态 `scale`） |
| 垂直判定 | 玩家普攻固定 `dy <= 70`；玩家技能用 `height`；敌人用 `hit_height` |
| 朝向判定 | `in_front = (dx == 0) or (sign(dx) == facing)`，即只打正前方 |
| `both` 例外 | 回身横扫 / 武器越过原点甩到身后的招式，配置 `both: true` 后前后两侧都判 |
| 判定时刻 | 出了起手后第 `hit_at` 秒结算，单位=动画秒；取武器/身体实际进入有效攻击位置的画面，最远伸展峰值只作候选，必须逐帧复核 |
| 提前量 | **已删除** 旧的统一提前 10%（`hit_at * 0.9`），它是"动画还没打到就掉血"的系统性根源 |
| 收招 | 锁定时长取动画真实时长（Boss/小怪由骨架查表，玩家技能 `_skill_durations` 运行时缓存） |

## 三、小怪 / 精英（7 种）

### 3.0 敌人技能释放准则（长期有效）

后续优化普通怪与精英时，统一遵守以下规则；这条优先级高于旧版“普攻占主导”的设计：

1. **首招是唯一普攻**：每个敌人的招式 1 没有独立冷却，只受公共出手间隔限制；不得再给其他招式设置“无独立冷却”。
2. **其余招式全部是技能**：每个技能必须有独立冷却，从实际起手时开始计时。配置漏写时共用 AI 自动补 8 秒兜底，但正式配置仍应显式填写。连段收尾属于主招，不另算技能、不重复计时。
3. **合规技能就绪时优先释放**：技能不得与普攻放进同一个权重池混抽；多个技能同时可用时，才在技能池内部按权重或最近射程规则选取。
4. **所有技能不可用时才回普攻**：技能处于冷却、距离不合规或触发条件不满足时，使用首招普攻；普攻也够不着则继续贴近，禁止拿远程或追击技能违规兜底。
5. **数值集中配置**：权重、独立冷却、距离窗口与主动触发方式写入 `enemy_types.gd` 的 `attack_rules`；测试必须逐个覆盖首招零冷却、技能独立冷却、技能优先、冷却禁重入、冷却结束恢复优先和普攻兜底。
6. **逻辑招式与演出分离**：需要让不同招式复用同一条 Spine 动画时，用 `move_anims` 建立逻辑键到真实动画名的映射；判定、伤害、连段和冷却仍按逻辑键读取，图鉴预览使用真实动画名。
7. **精英高伤倒地按需实装**：以后只有用户明确提到该精英、且受击 / 倒地 / 起身动画齐全时才配置此机制；未提到的精英暂时不加。当前双镰、青笠与青魇剑主均为**严格大于 5 点伤害**才触发，5 伤本身不倒地；普通怪既有规则不变，刀客与刺客仍在伤害达到 2 时触发，蛮兵维持全程霸体。

刀客、蛮兵、刺客、双镰与青笠的特殊技能冷却采用原版 1.2 倍；黑袍与青魇按各自招式配置，公共普攻出手间隔不变。

刀客当前落地值：亡命三刀为唯一普攻；双镰限 164px 内、独立冷却 7.2 秒；螺旋鞭只在 180～400px 主动触发、独立冷却 9.6 秒；升龙刀只在原追击瞬身窗口触发、独立冷却 14.4 秒。双镰合规且就绪时优先于亡命三刀，其冷却期间才回到普攻。

蛮兵当前落地值：开天为唯一普攻；辟地限 164px 内、独立冷却 10.8 秒；赶山三斧只在追击 120～260px 窗口主动触发、独立冷却 19.2 秒，不进入近身随机池。连段前半以 85px/s 推进，两劈各 1 伤，随后原地大劈 2 伤并静默力竭 3 秒；力竭属于同一招恢复段，不显示控制提示。被动「蛮力」让每段实伤附带 140px/s 水平的短击退初速，并提供全程霸体；普通控制、受击硬直与直接牵引无效，`ignore_armor` 控制与时停仍可穿透。

黑袍剑客当前落地值：`atk01` 为唯一普攻，`atk02 / atk03` 独立冷却分别为 7.2 / 9.6 秒。青魇剑主当前落地值：「亭台剑」为唯一普攻，「转 / 藏剑式」独立冷却分别为 7.2 / 9.6 秒；合规技能就绪时同样优先于亭台剑。

## 六、数据来源与复测流程

1. 运行 `scenes/tests/range_probe.tscn`，洋红背景、`PROBE_SCALE = 0.35`、`ORIGIN = (640, 660)`、60Hz 采样，逐帧记录剪影左右最远像素，写入 `tests/out/reach.json`，格式 `[t, 左侧伸展, 右侧伸展]`（单位=scale 1 骨架像素）。
2. 先用伸展的局部峰值筛选候选时刻，再用 Spine 冻结帧逐帧核对武器真正扫入有效攻击位置的画面，以该画面确定 `hit_at` 与同帧伸展量；不得把后段举斧、转身或收招的最远姿势误当命中帧。
3. `range = 命中帧骨架像素 × 该形态 scale`；若武器实际扫到原点左侧而美术朝右，则该招标记 `both`。
4. 修改后跑回归：`boss_test`（`_debug` / `c009` / `c015a1` / `c001` / `c008` / `c032` 均跑到 `ALL DONE`：登场→两次变身→冲锋→斩杀→结算）、`player_test`、`room_test`。

### 判定与实测的对应关系

- 判定距离以**角色节点原点**为基准，剪影测量同样以原点为基准（root motion 造成的位移已包含在剪影里，两者自洽）。
- 剪影包含披风、背挂武器等非攻击部件，个别招式（c009 skill07/08）峰值被坐骑主体主导，只按实测微调 range，判定时刻保留原值。
